# Tank Nexus — نسخه آنلاین بدون ترمینال (v0.4)

این بسته ادامهٔ فایل بازی اصلی Tank Nexus است. **هیچ‌یک از بازیکن‌ها نیاز به نصب برنامه، Node.js، CMD یا ترمینال ندارند.** پس از یک بار انتشار پروژه توسط مالک روی هاست، همهٔ بازیکن‌ها فقط آدرس سایت را باز می‌کنند.

## راه‌اندازی یک‌بارهٔ سایت بدون دستور و ترمینال

نیاز است مالک پروژه یک حساب GitHub و یک حساب Render داشته باشد. در این مرحله تنها از مرورگر و دکمه‌های سایت‌ها استفاده می‌کنید:

1. فایل ZIP را از حالت فشرده خارج کنید. چهار فایل `index.html` و `server.js` و `package.json` و `render.yaml` برای انتشار ضروری‌اند.
2. در مرورگر به https://github.com/new بروید و یک مخزن تازه ایجاد کنید (مثلاً `tank-nexus-online`).
3. در صفحهٔ مخزن روی **Add file → Upload files** بزنید، چهار فایل بالا را با هم انتخاب کنید و **Commit changes** را بزنید. فایل‌ها باید در **ریشهٔ مخزن** باشند، نه داخل پوشهٔ دیگر.
4. وارد https://dashboard.render.com/ شوید؛ از **New → Blueprint** استفاده کنید، حساب GitHub و مخزن جدید را وصل کنید. فایل `render.yaml` خودکار تنظیمات Node.js و ساخت پروژه را مشخص می‌کند.
5. **Apply / Deploy Blueprint** را تأیید کنید. Render خودش وابستگی‌ها را نصب می‌کند و سرور Node.js را اجرا می‌کند؛ این دستورها را خودتان اجرا نمی‌کنید.
6. وقتی وضعیت سرویس **Live** شد، آدرس HTTPS نمایش‌داده‌شده برای سرویس را باز کنید. این آدرس، لینک واقعی بازی شماست. آدرس عمومی از قبل مشخص نیست و تا استقرار انجام نشود نمی‌توانیم یک لینک قابل‌بازی بدهیم.

> `render.yaml` به‌صورت پیش‌فرض پلن `free` و منطقهٔ Frankfurt را انتخاب می‌کند. سرویس رایگان Render ممکن است پس از ۱۵ دقیقه بی‌ترافیکی خوابیده و در هنگام بیدارشدن تأخیر داشته باشد؛ همچنین ممکن است در هر زمان راه‌اندازی مجدد شود. برای اجرای پایدارتر، در پنل Render پلن پولی مناسب انتخاب کنید. در نسخه فعلی اتاق‌ها در حافظهٔ سرویس‌اند و با ری‌استارت پاک می‌شوند. برای پروژه بزرگ و پایداری تولیدی باید پایگاه‌داده و مدیریت بازیابی نشست اضافه شود.

## روش بازی دو نفره (یا حداکثر چهار نفر)

1. بازیکن اول **لینک HTTPS سایت** را باز می‌کند و `START COMBAT` → `Multiplayer` → `SIMPLE MULTI` یا `OUTPOST ROYALE` → `Create Room` را می‌زند.
2. روی `COPY INVITE LINK` می‌زند و لینک را برای نفر دوم ارسال می‌کند؛ یا فقط کد ۵ کاراکتری اتاق را می‌فرستد.
3. نفر دوم لینک دعوت را باز می‌کند، نامش را وارد می‌کند و **Connect** را می‌زند. در لینک دعوت، کد اتاق خودکار پر می‌شود.
4. نفر اول پس از ورود دو بازیکن دکمهٔ **START MULTIPLAYER GAME** را می‌زند.

**مهم:** خود بازی و ارتباط WebSocket روی همان آدرس اجرا می‌شوند و به‌صورت خودکار از `wss://` زیر HTTPS استفاده می‌کنند. به هیچ کادر آدرس سرور یا IP نیاز نیست. برای پایداری بازی در این نسخه مرورگر سازندهٔ اتاق باید باز بماند.

## تفاوت با v0.3

- هیچ کادر دستی برای آدرس WebSocket در لابی وجود ندارد.
- لینک دعوت با کد اتاق و مود بازی اضافه شده است.
- ورودی‌های حرکت به صف محدود می‌روند و در تیک ۳۰ هرتز روی سرور اعمال می‌شوند، نه مستقیماً با رسیدن بسته.
- کد ارسال وضعیت جهان مختصرتر شده و سقف مجاز پیام شبکه برای نبردهای شلوغ افزایش یافته است.
- نسخه سرور و HTML در یک سرویس میزبانی اجرا می‌شوند.

## محدودیت‌های معماری کنونی

- سرور Node.js جای بازیکن‌ها و اتاق‌ها را کنترل می‌کند، **ولی شبیه‌سازی دشمنان، موج‌ها و منطق قدیمی جنگ هنوز روی مرورگر میزبان است**. پس اگر میزبان خارج شود، بازی متوقف می‌شود. این نسخه هنوز معماری کاملاً سرورمحور نیست.
- ذخیرهٔ اتاق‌ها دائمی نیست و بازیابی خودکار پس از قطع اتصال یا ری‌استارت سرور هنوز پیاده‌سازی نشده است.
- بخش‌هایی مثل اقتصاد و ساخت‌وساز در حالت OUTPOST هنوز برای همهٔ کاربران کاملاً سرورمحور نشده‌اند.
- تست شبکهٔ دو کلاینت، ساخت اتاق، Join، Start و حرکت موفق بوده است؛ **تست کامل روی اینترنت واقعی با دو مرورگر و پینگ/اتلاف بسته انجام نشده**. عدم وجود کامل TP Back قابل تضمین نیست.
- اگر سرویس در چند Instance اجرا شود، اتاق‌های ذخیره‌شده در حافظه بین Instanceها مشترک نیستند؛ فعلاً باید روی **یک Instance** اجرا شود.

## بررسی کارکرد

پس از استقرار می‌توانید در مرورگر آدرس `https://YOUR-SITE/health` را باز کنید تا وضعیت کلی سرور و تعداد اتاق‌ها/بازیکنان را ببینید. نیازی به ترمینال نیست.

در آینده برای بازی با پایداری بالا: انتقال AI، برخوردها، آسیب، تیراندازی و اقتصاد به Node.js، پشتیبانی از reconnect و session recovery، بهبود فشرده‌سازی دلتا و تست مرورگرهای واقعی پیشنهاد می‌شود.
